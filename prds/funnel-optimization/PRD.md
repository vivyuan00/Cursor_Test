## 1. 需求背景与目标

### 1.1 业务背景

平台以AI舌诊引流、企微私域转化、医助服务、支付履约为核心闭环。当前缺少统一的全链路转化漏斗分析能力，无法稳定支撑运营决策优化。

全链路漏斗优化项目专注于：
- 从渠道引流到加企微的转化分析
- 从加企微到付费确认的完整转化漏斗（F01~F6）
- 医助服务人效与成交数据统计
- 渠道-产品-版本层级的核心指标与转化漏斗

### 1.2 需求目标

| 目标编号 | 目标描述 | 衡量方式 |
|----------|----------|----------|
| G01 | 建立全链路转化漏斗数据模型，支持每日数据统计 | 漏斗日汇总表稳定产出，F01~F6各步数据准确 |
| G02 | 提供多维度漏斗分析：时间维度、医助维度、渠道维度 | BI看板UAT通过，与业务抽样数据对账通过 |
| G03 | 支持渠道产品版本级转化漏斗下钻分析（舌诊类、快测类） | 产品详细转化数据页上线，支持按日期查看各步骤转化率 |
| G04 | 提供医助服务人效排行榜与成交数据对比 | 医助维度数据与总量可交叉验证 |

### 1.3 需求范围

**包含**：

- 漏斗日汇总数据模型（`dws_funnel_channel_assistant_1d`）
- 订单金额日汇总（按药物类型/初复诊）（`dws_order_drug_visit_1d`）
- 医助成交日汇总（`dws_assistant_trade_1d`）
- 渠道产品转化日汇总（`dws_channel_product_conversion_1d`）
- BI看板：每日数据统计、医助服务统计、渠道维度统计
- 产品详细转化数据页（下钻分析）

## 7. 页面与交互

### 7.2 全链路漏斗页

全链路漏斗页分为三大数据分析模块，分别从时间维度、医助维度和渠道维度提供多角度数据洞察。

#### 7.2.0 交互模型与筛选架构

##### 交互层级

```
一级 Tab（统计类型）: 每日数据统计 | 医助服务统计 | 渠道维度统计
    ↓ 选中后展示该类型的专属筛选栏
    ↓ 筛选栏下方
二级 Tab（数据子类）: 例如每日转化数据 | 每日订单金额数据
    ↓
核心区域: 上方可选图表（简单辅助） + 下方横纵坐标数据表（核心）
```

**设计原则：**

1. 用户先选择一级 Tab（统计类型），页面展示该类型的专属筛选栏
2. 筛选栏统一控制该类型下所有二级 Tab 的数据
3. 核心展示为**横坐标×纵坐标的数据表**，表格上方可放简单图表辅助可视化
4. 每个筛选栏末尾均有「查询」和「重置」按钮

##### 7.2.1.1 每日转化数据统计

[4] > **统计口径**：全链路漏斗分为两大类：AI工具转化和医助转化。
> - AI工具转化：统计从用户访问AI工具首页到加企微的转化链路
> - 医助转化：仅统计初诊流程转化，从加企微到付费确认的完整链路

**AI工具转化**

> **统计口径**：统计从用户访问AI工具首页到加企微的转化链路。

| 漏斗步骤 | 指标名称 | 说明 |
|----------|----------|------|
| A01 | 首页PV | AI工具首页页面浏览量或工具新建量，比如舌诊首页浏览量、快测对话页数量 |
| A02 | 首页UV | AI工具首页独立访客数 |
| A03 | 报告数 | 用户生成的舌诊/体质报告数 |
| A04 | 报告人次 | 生成报告的去重用户数 |
| A05 | 加企微数 | 通过AI工具新增企微好友去重人数 |
| A06 | 报告-加微转化率PV | 加企微数 / 报告数 |
| A07 | 首页-加微转化率PV | 加企微数 / 首页PV |

**医助转化**

> **统计口径**：仅统计**初诊流程**转化，从加企微到付费确认的完整链路。

| 漏斗步骤 | 指标名称 | 说明 |
|----------|----------|------|
| F01 | 加企微数 | 当日通过各渠道新增企微好友去重人数 |
| F02 | 开口数 | 用户主动发送首条消息的去重人数 |
| F03 | 舌象上传数 | 用户提交舌象图片的去重人数，本期可咱实现为用户上传图片即算 |
| F04 | 开方数 | 完成病例总结和开方的去重人数 |
| F05 | 支付数 | 支付成功的去重人数（R01） |
| F06 | 确认数 | 付费确认（含药房发货确认等最终节点）的去重人数 |
| F07 | 支付转化率 | 支付数 / 加企微数 |

**展示内容：**

| 区块 | 内容 | 格式 |
|------|------|------|
| AI工具转化漏斗图 | A01首页PV → A02首页UV → A03报告数 → A04报告人次 → A05加企微数，显示各步人数与环节转化率，底部显示报告-加微转化率PV、首页-加微转化率PV | 漏斗条形图，与医助转化并列展示 |
| 医助转化漏斗图 | F01加企微 → F02开口 → F03舌象上传 → F04开方 → F05支付 → F06确认，显示各步人数与环节转化率，底部显示支付转化率 | 漏斗条形图，与AI工具转化并列展示 |
| 数据表 | 纵坐标：日期；横坐标：AI工具转化（首页PV、首页UV、报告数、报告人次、加企微数、报告-加微转化率PV、首页-加微转化率PV）+ 医助转化（加企微、开口、舌象上传、开方、支付、确认、支付转化率） | 宽表格，支持横向滚动、排序、导出 |

##### 7.2.1.2 每日订单金额数据

[5] > **统计口径**：按业务日统计订单与金额，分别按药物类型、初复诊两个维度拆分。

**按药物类型拆分：**

| 指标 | 说明 |
|------|------|
| 汤剂订单数 | 当日药物类型为汤剂的支付成功订单数 |
| 汤剂订单金额 | 当日汤剂订单实付金额合计（R01） |
| 丸剂订单数 | 当日药物类型为丸剂的支付成功订单数 |
| 丸剂订单金额 | 当日丸剂订单实付金额合计（R01） |

**按初复诊拆分：**

| 指标 | 说明 |
|------|------|
| 初诊订单数 | 当日首次成交用户的支付成功订单数 |
| 初诊金额 | 当日初诊订单实付金额合计 |
| 复诊订单数 | 当日非首次成交（复购）用户的支付成功订单数 |
| 复诊金额 | 当日复诊订单实付金额合计 |

**汇总指标：**

| 指标 | 说明 |
|------|------|
| 总订单数 | 当日全部支付成功订单数（= 汤剂+丸剂 = 初诊+复诊） |
| 总订单金额 | 当日全部实付金额合计 |

**展示内容：**

| 区块 | 内容 | 格式 |
|------|------|------|
| 药物类型分析 | 汤剂/丸剂订单数与金额对比 | 分组柱状图或堆叠柱状图 |
| 初复诊分析 | 初诊/复诊订单数与金额对比 | 分组柱状图或饼图 |
| 趋势图 | 所选范围内每日总金额、初诊金额、复诊金额趋势 | 折线图 |
| 明细表 | 按日期展示：汤剂订单数、汤剂金额、丸剂订单数、丸剂金额、初诊订单数、初诊金额、复诊订单数、复诊金额、总订单数、总金额 | 表格，支持排序与导出 |

## 5. 业务规则

| 规则编号 | 规则描述 | 适用场景 |
|----------|----------|----------|
| R01 | 付费成功以订单payment_status=PAID且paid_at非空为准；GMV默认取实付金额paid_amount | GMV、支付转化率 |
| R02 | 漏斗步骤的进入/完成条件、去重主体（user_id或role_id）以指标字典为准，变更需走评审 | 漏斗看板、实验对比 |
| R03 | 漏斗冻结：已发布的日报pt在T+2日内仅允许因数据订正触发回补，须留审计记录 | 漏斗、管理考核 |
| R04 | 日切与时区统一为业务日pt（默认Asia/Shanghai）；报表展示须标注数据截至昨日 | BI与对外同步 |
| R05 | 归因若同时存在首触点与末次付费触点，须分卡或分字段展示，禁止混用单一字段解释ROI | 渠道分析 |

## 8. 验收标准（UAT）

| 编号 | 验收项 | 通过条件 |
|------|--------|----------|
| A01 | 漏斗看板-每日转化 | 与业务抽样至少100单路径核对F01~F06人数一致（允许已知口径差异备案） |
| A01a | 漏斗看板-每日订单金额 | 按药物类型（汤剂/丸剂）、初复诊拆分的订单数与金额与财务侧日报交叉校验，差异≤0.5%或备案说明 |
| A01b | 漏斗看板-医助服务人效 | 医助维度F01~F06各步人数与总量一致；排行榜数据与明细表可交叉验证 |
| A01c | 漏斗看板-医助成交数据 | 医助维度初诊/复诊订单数与金额之和等于总量；与每日订单金额数据可交叉验证 |
| A01d | 漏斗看板-渠道核心数据 | 渠道→子渠道→产品→版本层级数据可展开折叠；加企微率计算正确（PV/UV两种口径） |
| A01e | 漏斗看板-渠道产品转化漏斗（舌诊类） | 以舌诊产品为例，验证首页PV、舌象上传PV、舌诊报告数、对话数、小结数、留资数逐级递减合理；各转化率与折损率计算正确 |
| A01f | 漏斗看板-渠道产品转化漏斗（快测类） | 以快测类型产品为例，验证首页PV（会话数）、开口会话数、报告数量、加粉数逐级递减合理；会话开口率、首页-报告转化率、报告-加粉转化率、首页-加粉转化率计算正确 |
| A02 | GMV | 与财务/订单侧日报差异0或备案说明 |
| A03 | 权限 | 渠道账号不可见其他渠道；医助仅本人/本组 |
| A04 | 口径变更 | 执行一次模拟回补后，版本号与公告链路可追溯（R03） |
