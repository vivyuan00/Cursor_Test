## 一、项目背景

### 1.1 业务发展现状
公司致力于打造AI驱动、标准化与规模化并重的中医健康管理服务平台，通过舌诊工具及私域运营，为用户提供从问诊到处方的一站式服务。目前核心用户增长依赖百度等免费合作渠道，已积累150万存量用户，月GMV待提升至50万目标。随着业务扩张，现有系统在流量承接、转化效率、医生资源、数据能力等方面暴露出严重短板。

### 1.2 核心痛点

#### 痛点1: 业务流量不稳定，直接遏制核心目标达成
+ **现状**: 用户增长主要依赖百度的免费合作渠道，流量控制权不在自己手中
+ **问题**: 每日加粉数波动剧烈，团队工作节奏和系统承载价值被拉低
+ **影响**: 整体运营效率下降，核心增长目标无法稳定达成

#### 痛点2: 投放ROI待提升，用户流失严重
+ **现状**: 从用户进入舌诊工具首页到最终添加企业微信，转化率在0.5%-3%之间波动
+ **问题**: 不同渠道、工具之间转化差异大，缺少系统化优化手段
+ **影响**: 增长天花板较低，核心业务目标受限

#### 痛点3: 医助转化链路长且缺乏自动化，工作效率低
+ **现状**: 用户从舌诊→加微→医助沟通→问诊→处方→支付，流程耗时数天，大量依赖人工跟进。CRM自动化能力弱，缺少SOP触达、超时提醒、自动催付
+ **问题**: 医助精力被低效重复沟通占用，人效难提升
+ **影响**: 用户耐心有限，在等待医生确认或支付环节大量流失

#### 痛点4: 医生资源成为效率瓶颈，处方确认延迟
+ **现状**: 签约医生仅5人，病历和AI处方推送到医生工作台后需手动调整签字；系统无优先级排序、批量处理或自动提醒
+ **问题**: 医生响应速度不稳定
+ **影响**: 大量订单卡在“待确认”状态，用户长时间收不到支付码，体验差、流失率高，医生资源无法支撑业务翻倍增长

#### 痛点5: 未转化用户存量较大，激活空间明显
+ **现状**: 150万存量用户中，实际支付用户仅占15%左右，大部分处于“添加企微但未付费”状态
+ **问题**: 缺少有效的自动触达和激活策略
+ **影响**: 存量用户池中大量潜在价值被浪费

#### 痛点6: 数据孤岛严重，缺乏实时决策能力
+ **现状**: AI问诊数据、CRM、医生工作台、代煎中心等系统未完全打通；BI看板缺失，运营团队手动导出Excel分析
+ **问题**: 无法及时发现转化漏斗异常，策略调整滞后一周以上
+ **影响**: 无法做精细化用户分群和自动化运营，决策效率低下

#### 痛点7: AI能力还有提升空间
+ **现状**: 当前AI舌诊和分析准确性不够稳定，存在误判或漏判
+ **影响**: 直接或间接影响用户信任度和最终转化率，尤其对中医服务这种高信任门槛业务

#### 痛点8: 不同渠道存在合规风险
+ **现状**: 腾讯、合作换量等渠道各有审核门槛和限制；业务涉及舌象、病历、处方等高敏感健康数据，互联网诊疗政策日益严格
+ **影响**: 一旦出现数据泄露或合规问题，可能导致业务叫停甚至法律处罚，是长期发展的重大隐患

## 二、项目目标

### 2.1 总体目标
**成为国内领先的AI驱动、标准化与规模化并重的中医健康管理服务平台**，通过技术降低对个人经验的依赖，实现用户从“体验工具”到“信赖服务”的高效转化，最终建立中医私域运营的行业标杆，并完成上市目标。

### 2.2 具体目标

#### 业务目标
+ **GMV**: 月GMV达到50万
+ **私域企微好友数**: [目标值待补充]
+ **加微→付费转化率**: [目标值待补充]
+ **医助人效**: 人均服务付费用户数/月 [目标值待补充]
+ **用户复购率**: 3个月内复购率 [目标值待补充]

#### 系统目标
通过系统重构与数据中台建设，构建“可归因、可自动化、可量化、可合规”的技术底座：

1. **多渠道统一管理与流量波动缓冲机制**
   - 建设渠道管理平台，实时监控各渠道加粉量与稳定性
   - 增加流量波动预警与自动调配功能
   - 引入用户增长归因模型

2. **全链路漏斗分析与投放优化闭环**
   - 打通投放→首页→加微→沟通→付费全链路数据，提供实时转化漏斗看板
   - 支持按渠道、素材、时段拆分转化率，自动计算ROI
   - 落地页A/B测试工具，BI看板小时级可调

3. **自动化转化引擎，降低人工依赖**
   - CRM中增加自动化SOP工作流（欢迎语、问诊引导、话术推荐、超时提醒、自动催付）
   - 建设话术中台，支持优秀话术沉淀、场景推荐、对话质检
   - 医助工作台效率看板

4. **极致提升医生人效，辅助AI减少医生工作量**
   - 医生工作台优化：智能排序、批量操作、移动端签批
   - AI辅助审方：学习医生调整习惯，自动建议修改；处方模板库
   - 紧急升级机制：超时自动提醒并升级

5. **存量用户激活与生命周期管理系统**
   - CRM中建立用户分层标签，配置自动激活SOP
   - 流失预警模型，提前触发干预

6. **数据中台与实时BI看板**
   - 打通6大数据源，建设用户行为数仓
   - 实时转化漏斗看板（分钟级），支持自助分析
   - 自定义异常监控与告警

7. **AI持续迭代与反馈闭环**
   - AI样本标注平台，医生可标记AI建议正确/错误
   - 每月迭代舌诊模型和问诊Agent，准确率每月提升2个百分点
   - 低置信度结果自动转人工复核

8. **渠道合规管控与数据安全体系**
   - 合规审核模块：自动检测素材违规内容
   - 敏感数据脱敏处理
   - 操作日志全记录与用户授权管理

## 三、项目范围

### 3.1 In Scope（本期实施）

#### Phase 1: 核心转化引擎与渠道管理（P0 - 3个月）
+ **渠道管理平台**: 多源渠道统一接入（百度、腾讯、抖音、合作换量），流量监控与预警，自动调配功能
+ **全链路漏斗分析**: 打通投放→工具首页→加微→沟通→付费数据，实时转化漏斗看板，渠道ROI计算
+ **落地页A/B测试工具**: 支持快速验证高转化页面
+ **自动化SOP基础能力**: 加微自动欢迎语、问诊引导、超时提醒（企微/短信）

#### Phase 2: 数据中台与自动化引擎（P1 - 3个月）
+ **数据中台建设**: 打通AI舌诊、企微沟通、CRM、医生工作台、代煎中心、支付6大系统，建设用户行为数仓
+ **实时BI看板**: 分钟级更新，支持按渠道、时段、医助等维度下钻，自定义异常告警
+ **自动化转化引擎增强**: 话术中台（话术沉淀、场景推荐、对话质检），SOP工作流（自动催付、基于用户行为的触发），医助工作台效率看板
+ **存量用户激活系统**: 用户分层标签，自动激活SOP（7天未沟通、开方未支付、已支付未复购等），流失预警模型

#### Phase 3: 医生赋能与AI迭代（P2 - 2个月）
+ **医生工作台重构**: 智能排序（高意向/高客单价/即将流失订单置顶），批量处方操作，移动端签批
+ **AI辅助审方**: 学习医生调整历史，自动建议修改，处方模板库一键应用
+ **紧急升级机制**: 订单待确认超2小时自动提醒，超4小时升级至备用医生
+ **AI样本标注平台**: 医生一键标记AI建议正确/错误，积累训练数据
+ **舌诊与问诊模型迭代**: 每月准确率提升2个百分点

#### Phase 4: 合规与安全体系（P2 - 1个月）
+ **渠道合规审核模块**: 自动检测投放素材违规关键词、医疗宣称
+ **数据安全体系**: 敏感数据脱敏（人脸模糊、姓名隐藏），操作日志全记录，用户授权管理

### 3.2 Out of Scope（暂不实施）
+ 线下实体诊所管理系统
+ 中药代煎中心的物理物流系统（仅做数据对接）
+ 自建支付网关（依赖现有支付通道）
+ 硬件设备（舌诊采集设备等）

## 七、项目风险

### 7.1 业务风险
+ **流量波动风险**: 百度等合作渠道政策变化，导致加粉量断崖式下降
+ **医生配合度**: 医生工作繁忙，可能抵触系统变更或标注任务
+ **用户迁移抵触**: 新流程可能导致老用户短期体验下降

### 7.2 技术风险
+ **数据孤岛打通难度**: 6大系统接口不标准，历史数据质量差
+ **AI准确率提升不及预期**: 每月2个百分点目标可能过于激进
+ **实时BI性能**: 分钟级更新在数据量大时可能导致看板延迟

### 7.3 项目管理风险
+ **进度延期**: 医生工作台等依赖外部反馈的模块易延期
+ **人员流失**: 数据工程师和AI算法人才关键
+ **合规审查滞后**: 安全方案可能需多次过会，拖慢上线
