## 主要用户

### 产品经理（Primary User）

#### 基本画像

- **角色**：B端产品经理
- **工作年限**：1-5年
- **主要职责**：需求分析、PRD撰写、原型设计、需求评审
- **工作场景**：ERP系统、供应链系统、内部管理系统等

#### 痛点

1. **文档工作量大**：PRD撰写耗时，字段清单整理繁琐
2. **标准化不足**：文档格式不统一，容易遗漏关键信息
3. **原型工作量大**：需要依赖设计师和开发才能看到效果
4. **知识分散**：项目经验和最佳实践缺少沉淀

#### 需求

- 快速生成标准化的PRD文档
- 自动整理字段清单
- 快速生成前端Demo验证想法
- 沉淀项目经验和知识

#### 使用场景

1. **日常需求分析**：接到新需求后，快速梳理字段清单和业务规则
2. **PRD撰写**：使用模板和工作流快速生成PRD文档
3. **方案验证**：生成前端Demo，快速验证UI和交互方案
4. **需求评审**：使用流程图和数据推演说明业务逻辑
5. **知识查询**：查阅过往项目的经验和最佳实践

## 用户画像总结

### 用户能力分布

- **AI协作经验**：初级-中级（需要清晰的引导和模板）
- **技术能力**：了解前端基础（能看懂TypeScript和React代码）
- **业务能力**：熟悉B端业务（ERP、供应链等）

### 用户期望

1. **简单易用**：不需要学习复杂的工具，工作流自动引导
2. **快速见效**：能立即提升工作效率，减少重复劳动
3. **质量保证**：生成的文档和Demo符合专业标准
4. **可定制**：可以根据自己的项目调整模板和规范

### 使用频率

- **高频场景**（每周使用）：
  - 创建PRD文档
  - 整理字段清单
- **中频场景**（每月使用）：
  - 生成前端Demo
  - 业务流程分析

- **低频场景**（按需使用）：
  - 更新模板和规范
  - 查阅历史经验

## 用户旅程（User Journey）

### 新用户首次使用

1. **了解项目**：阅读README.md和AGENT.md
2. **熟悉结构**：了解文件夹组织和模板
3. **尝试工作流**：使用`/create-field-list`生成第一个字段清单
4. **生成PRD**：使用`/create-prd`生成第一个PRD文档
5. **验证效果**：生成前端Demo验证方案

### 日常使用流程

1. **接到需求**：收到新的业务需求
2. **分析需求**：使用`/analyze-business`分析业务流程
3. **整理字段**：使用`/create-field-list`整理字段清单
4. **撰写PRD**：使用`/create-prd`生成PRD文档
5. **生成Demo**：使用`/create-frontend-demo`生成前端Demo
6. **需求评审**：使用PRD和Demo进行需求评审

### 高级使用场景

1. **定制模板**：根据项目特点调整PRD模板
2. **创建技能包**：将常用的分析方法沉淀为技能包
3. **更新规范**：完善项目规则和最佳实践
4. **知识沉淀**：在AGENT.md中记录项目经验
