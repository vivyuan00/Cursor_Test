1. 需求背景与目标

1.1 业务背景

「用户转化明细」是全链路漏斗优化看板的核心下钻页面，用于追踪单用户从线索（加粉）→ 沟通 → 开方 → 成交的全链路转化情况。运营、流量组长、医助管理者依赖该页面进行个案排查、转化归因与数据导出分析。

本轮改造的核心目的，是拓展明细数据的可筛范围与使用场景：在既有「加粉时间」口径上增加「支付时间」维度、在核心列表补充支付时间与复诊信息、补充应用/应用版本筛选，使明细页不仅能独立排查个案，还能承接全链路漏斗汇总表的下钻——从漏斗任意汇总行一键跳入明细，并自动带入对应日期、渠道、医助等筛选条件。

问题现状影响
时间维度单一仅支持按「加粉时间」筛选无法按支付节点复盘转化，也无法承接漏斗「支付/订单」口径下钻
成交信息过简成交信息仅展示「开方状态」「成交状态」初诊/复诊成交细节不足，无法与漏斗订单口径对齐
加粉状态不可筛列表展示加粉状态，但无筛选项无法快速定位重复添加、已删除用户
漏斗与明细割裂汇总表无法一键进入明细运营需手工重选筛选条件，排查效率低
导出超时同步导出，前端一次性拉取全量数据生成 Excel筛选数据量大时导出失败，影响运营取数

3. 页面与交互

3.1 页面结构

页面标题：用户转化数据明细表

副标题动态展示当前时间维度，例如：线索 → 沟通 → 开方 → 成交 · 全链路转化监控（当前时间筛选：加粉时间）

页面自上而下分为：

  1. 筛选栏（随时间维度显隐部分筛选项）
  2. 统计卡片区 + 趋势图（卡片集合随时间维度切换）
  3. 核心数据列表（宽表格，支持横向滚动、分页）
  4. 底部分页与说明

3.2.1 时间维度切换规则

时间维度筛选字段列表命中逻辑筛选项统计卡片
加粉时间（默认）add_wx_at加粉时间落在日期范围内展示加粉状态、响应状态、初诊开方/初诊成交/复诊成交状态见 3.5「加粉时间」卡片集
支付时间初诊 first_paid_at 或复诊支付时间初诊支付或任一复诊支付时间落在日期范围内即命中；两端均无支付则不命中隐藏加粉状态、响应状态、初诊开方状态、初诊成交状态、复诊成交状态见 3.5「支付时间」卡片集

交互说明：

  1. 切换时间维度后，快捷文案、日期标签、筛选项显隐、统计卡片布局同步更新；已选日期范围保留不清空。
  2. 支付时间维度下被隐藏的筛选项不参与查询（等同于「全部」）。
  3. 页脚说明同步更新当前时间维度。

3.2.2 应用与应用版本筛选规则

应用可选版本
舌诊v3.2、v2.1
体质测试v3.2、v1.0
问诊H5v2.1、v1.0

切换应用后版本重置为「全部」。

3.2.3 状态筛选规则

加粉状态（由 是否删除、重复添加 派生）：

展示值判定规则
正常是否删除 = 否 且 重复添加 = 否
重复添加重复添加 = 是（优先于已删除）
已删除是否删除 = 是 且 重复添加 = 否

初诊开方状态：已开方 = 存在初诊处方；未开方 = 无。

初诊成交状态：已成交 = 初诊支付成功；未成交 = 未支付（含未开方）。

复诊成交状态：已成交 = 复诊次数 > 0；未成交 = 复诊次数 = 0。

3.2.4 渠道筛选与「全部渠道」口径（U07）

适用于：数据统计中的每日数据统计（每日转化、每日订单金额）、医助维度统计（医助服务人效、医助成交），以及用户转化明细的渠道筛选。渠道维度统计表本身按渠道行展开，不改变「全部」默认逻辑。

规则说明
默认值渠道筛选默认 = 全部
「全部」含义包含所有渠道来源的加粉 / 支付 / 订单数据，不限于通过 AI 工具（舌诊、体质测试、问诊 H5 等）转化进线的用户
非工具归集凡非通过 AI 工具转化来的流量 / 加粉（如线下转介绍、自然添加、其他人工转介等），统一归入渠道 「线下转介绍等」
选项位置渠道下拉在既有 AI / 投放等渠道选项之后，最后一项增加「线下转介绍等」
筛选行为选择具体 AI 渠道时，仅返回该渠道数据；选择「线下转介绍等」时，仅返回非工具来源数据；选择「全部」时上述两类一并统计

渠道选项示意（顺序，具体投放渠道名称沿用现网）：

全部
├─ baidu_doctor_h5 / 百度巧舱 …
├─ douyin_info …
├─ weixin_mp …
└─ 线下转介绍等    ← 新增，置于末尾；非 AI 工具转化均归入此渠道

口径说明：

  1. 每日转化、每日订单金额、医助人效、医助成交在默认「全部」下，汇总数字 = AI 工具各渠道合计 + 「线下转介绍等」。
  2. 「线下转介绍等」用户通常无应用 / 应用版本（或为空）；明细列表对应字段展示 — 或空，不影响筛选。
  3. 从漏斗下钻至明细时：若漏斗当前选的是「全部」，明细带入渠道=全部；若选的是「线下转介绍等」，明细带入该渠道。

3.3 漏斗汇总表下钻明细（U05）

在全链路漏斗各汇总表最右侧新增（或调整）操作列，链接至用户转化明细页，并通过页内跳转带入时间维度与筛选项；明细页落地后自动按带入条件执行一次筛选。

> 原型实现：数据统计2.html 为合一页（左侧导航：全链路漏斗 / 用户转化明细）。操作列点击后切换至明细 Tab，并自动写入筛选条件后查询（不再新开独立页面）。

来源页面操作文案带入明细的筛选条件
每日转化数据加粉明细时间维度=加粉时间；日期起止=该行日期；渠道/子渠道/应用等=当前漏斗筛选条件
每日转化数据支付明细时间维度=支付时间；日期起止=该行日期；渠道等筛选项带入
每日订单金额数据数据明细时间维度=支付时间；日期起止=该行日期；渠道等筛选项带入
医助服务人效统计加粉明细时间维度=加粉时间；日期起止=当前查询日期范围；医助企微 ID（或医助账号）；渠道等筛选项带入
医助服务人效统计支付明细时间维度=支付时间；日期起止=当前查询日期范围；医助企微 ID；渠道等筛选项带入
医助成交数据数据明细时间维度=支付时间；日期起止=当前查询日期范围；医助企微 ID；渠道等筛选项带入
渠道维度数据转化详细（原「查看详情」改名）仍进入渠道产品详细转化页（原逻辑不变）
渠道维度数据加粉明细时间维度=加粉时间；带入该行渠道、子渠道、应用(产品)、应用版本；日期=当前查询范围
渠道维度数据支付明细时间维度=支付时间；带入同上渠道维度字段；日期=当前查询范围

3.4 异步导出 Excel（U01）

3.4.1 交互流程

用户点击「导出 Excel」
    ↓
校验：是否已执行筛选（detailQueried = true）
    ↓ 否 → Toast「请先筛选数据后再导出」
    ↓ 是
按钮置灰 + 文案变为「导出中...」
    ↓
后端创建导出任务（携带当前全部筛选条件快照）
    ↓
前端轮询任务状态
    ↓
成功 → Toast「导出成功」+ 下载；失败/超时 → 提示原因并恢复按钮

3.4.2 导出字段

分组导出列
线索信息患者编号、患者昵称、医助名、医助账号、所属团队、渠道、子渠道、应用、应用版本、报告时间、加粉时间、加粉状态
沟通信息患者对话数、医助回复数、患者图片数、响应状态
初诊成交信息开方状态、支付状态、支付时间
复诊成交信息复诊次数、复诊支付时间
扩展字段开方时间、首单编号、开单医生、首单金额、剂型(汤剂/丸剂)、物流发货时间、成交周期

文件命名：用户转化追踪明细_{时间维度}_{开始日期}_{结束日期}_{导出时间}.xlsx

3.5 统计卡片与趋势图

统计基准跟随「时间维度」。卡片主数字为加总；汤剂 / 丸剂以弱层级副文案展示（如 汤剂 12 单 · 丸剂 8 单）。

3.5.1 时间维度 = 加粉时间

统计卡片统计口径
添加用户数全部渠道加粉次数（删除后重新添加会累加，不去重）
已开口用户数客户对话数 > 0 的加粉记录数
初诊成交单数初诊支付成功订单数；副文案：汤剂 x 单、丸剂 x 单
初诊成交金额初诊实付金额合计；副文案：汤剂 / 丸剂金额
复诊成交单数复诊支付成功订单数；副文案：汤剂 x 单、丸剂 x 单
复诊成交金额复诊实付金额合计；副文案：汤剂 / 丸剂金额

3.5.2 时间维度 = 支付时间

统计卡片统计口径
初诊成交单数支付日期落在筛选范围内的初诊订单数；副文案：汤剂 / 丸剂
初诊成交金额同上口径金额；副文案：汤剂 / 丸剂
复诊成交单数支付日期落在筛选范围内的复诊订单数；副文案：汤剂 / 丸剂
复诊成交金额同上口径金额；副文案：汤剂 / 丸剂

点击卡片切换右侧趋势图聚合指标；对比功能沿用现状，对比基准日期随当前时间维度计算。

趋势图 X 轴：单日按小时、多日按天，时间字段与当前时间维度一致。
