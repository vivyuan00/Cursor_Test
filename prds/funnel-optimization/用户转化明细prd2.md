## 1. 需求背景与目标

### 1.1 业务背景

「用户转化明细」是全链路漏斗优化看板的核心下钻页面，用于追踪单用户从线索（加粉）→ 沟通 → 开方 → 成交的全链路转化情况。运营、流量组长、医助管理者依赖该页面进行个案排查、转化归因与数据导出分析。

本轮改造的核心目的，是**拓展明细数据的可筛范围与使用场景**：在既有「加粉时间」口径上增加「支付时间」维度、在核心列表补充支付时间与复诊信息、补充应用/应用版本筛选，使明细页不仅能独立排查个案，还能承接全链路漏斗汇总表的下钻——从漏斗任意汇总行一键跳入明细，并自动带入对应日期、渠道、医助等筛选条件。

| 问题 | 现状 | 影响 |
|------|------|------|
| 时间维度单一 | 仅支持按「加粉时间」筛选 | 无法按支付节点复盘转化，也无法承接漏斗「支付/订单」口径下钻 |
| 成交信息过简 | 成交信息仅展示「开方状态」「成交状态」 | 初诊/复诊成交细节不足，无法与漏斗订单口径对齐 |
| 加粉状态不可筛 | 列表展示加粉状态，但无筛选项 | 无法快速定位重复添加、已删除用户 |
| 漏斗与明细割裂 | 汇总表无法一键进入明细 | 运营需手工重选筛选条件，排查效率低 |
| 导出超时 | 同步导出，前端一次性拉取全量数据生成 Excel | 筛选数据量大时导出失败，影响运营取数 |

### 1.2 需求目标

| 目标编号 | 目标描述 | 衡量方式 |
|----------|----------|----------|
| G01 | 支持加粉/支付双时间维度，筛选与统计口径随维度切换 | 切换后筛选项、统计卡片、列表、趋势图口径一致 |
| G02 | 核心列表直接展示支付时间与复诊关键字段 | 无需展开详情即可查看支付时间、复诊次数/时间 |
| G03 | 支持加粉状态及初诊/复诊成交状态精准筛选 | 结果与列表展示状态一致 |
| G04 | 全链路漏斗汇总表可一键下钻至明细 | 各表操作列链接带入正确时间维度与筛选项 |
| G05 | 支持大数据量场景下的稳定数据导出 | 10 万条以内筛选结果异步导出成功率 ≥ 99% |
| G06 | 每日数据 / 医助维度默认覆盖全部渠道口径 | 默认「全部」含 AI 工具渠道 + 非工具「线下转介绍等」 |

## 3. 页面与交互

### 3.1 页面结构

页面标题：**用户转化数据明细表**

副标题动态展示当前时间维度，例如：`线索 → 沟通 → 开方 → 成交 · 全链路转化监控（当前时间筛选：加粉时间）`

页面自上而下分为：

1. 筛选栏（随时间维度显隐部分筛选项）
2. 统计卡片区 + 趋势图（卡片集合随时间维度切换）
3. 核心数据列表（宽表格，支持横向滚动、分页）
4. 底部分页与说明

### 3.2 筛选项

| 筛选项 | 类型 | 默认值 | 可见性 | 说明 |
|--------|------|--------|--------|------|
| **时间维度** | 单选下拉 | 加粉时间 | 始终 | 加粉时间 / 支付时间 |
| 时间快捷 | 按钮组 | 今日 | 始终 | 今日 / 昨日 / 近7天 / 近30天 |
| 日期起 / 止 | 日期 | 今日 | 始终 | 标签随时间维度变为「加粉日期」或「支付日期」 |
| 所属渠道 / 子渠道 | 下拉 | 全部 | 始终 | 子渠道随渠道联动；渠道选项末尾含「线下转介绍等」，见 3.2.4 |
| 应用 / 应用版本 | 下拉 | 全部 | 始终 | 版本随应用联动 |
| 所属团队 | 下拉 | 全部 | 始终 | 沿用现状 |
| 医助名(搜索) | 输入框 | — | 始终 | 支持姓名 / 企微账号模糊搜索 |
| **加粉状态** | 下拉 | 全部 | 仅加粉时间 | 全部 / 正常 / 重复添加 / 已删除 |
| **响应状态** | 下拉 | 全部 | 仅加粉时间 | 全部 / 优 / 良 / 差 |
| **初诊开方状态** | 下拉 | 全部 | 仅加粉时间 | 原「开方状态」；全部 / 已开方 / 未开方 |
| **初诊成交状态** | 下拉 | 全部 | 仅加粉时间 | 原「成交状态」；全部 / 已成交 / 未成交 |
| **复诊成交状态** | 下拉 | 全部 | 仅加粉时间 | **新增**；全部 / 已成交 / 未成交 |
| 昵称/编号 | 输入框 | — | 始终 | 患者昵称或编号模糊搜索 |
| 操作 | 按钮组 | — | 始终 | 「筛选」「重置」「导出 Excel」 |

#### 3.2.1 时间维度切换规则

| 时间维度 | 筛选字段 | 列表命中逻辑 | 筛选项 | 统计卡片 |
|----------|----------|--------------|--------|----------|
| 加粉时间（默认） | `add_wx_at` | 加粉时间落在日期范围内 | 展示加粉状态、响应状态、初诊开方/初诊成交/复诊成交状态 | 见 3.5「加粉时间」卡片集 |
| 支付时间 | 初诊 `first_paid_at` 或复诊支付时间 | 初诊支付或任一复诊支付时间落在日期范围内即命中；两端均无支付则不命中 | **隐藏**加粉状态、响应状态、初诊开方状态、初诊成交状态、复诊成交状态 | 见 3.5「支付时间」卡片集 |

**交互说明**：

1. 切换时间维度后，快捷文案、日期标签、筛选项显隐、统计卡片布局同步更新；已选日期范围**保留不清空**。
2. 支付时间维度下被隐藏的筛选项不参与查询（等同于「全部」）。
3. 页脚说明同步更新当前时间维度。

#### 3.2.2 应用与应用版本筛选规则

| 应用 | 可选版本 |
|------|----------|
| 舌诊 | v3.2、v2.1 |
| 体质测试 | v3.2、v1.0 |
| 问诊H5 | v2.1、v1.0 |

切换应用后版本重置为「全部」。

#### 3.2.3 状态筛选规则

**加粉状态**（由 `是否删除`、`重复添加` 派生）：

| 展示值 | 判定规则 |
|--------|----------|
| 正常 | 是否删除 = 否 且 重复添加 = 否 |
| 重复添加 | 重复添加 = 是（优先于已删除） |
| 已删除 | 是否删除 = 是 且 重复添加 = 否 |

**初诊开方状态**：已开方 = 存在初诊处方；未开方 = 无。

**初诊成交状态**：已成交 = 初诊支付成功；未成交 = 未支付（含未开方）。

**复诊成交状态**：已成交 = 复诊次数 > 0；未成交 = 复诊次数 = 0。

#### 3.2.4 渠道筛选与「全部渠道」口径（U07）

适用于：**数据统计**中的每日数据统计（每日转化、每日订单金额）、医助维度统计（医助服务人效、医助成交），以及用户转化明细的渠道筛选。渠道维度统计表本身按渠道行展开，不改变「全部」默认逻辑。

| 规则 | 说明 |
|------|------|
| 默认值 | 渠道筛选默认 = **全部** |
| 「全部」含义 | 包含**所有渠道来源**的加粉 / 支付 / 订单数据，**不限于**通过 AI 工具（舌诊、体质测试、问诊 H5 等）转化进线的用户 |
| 非工具归集 | 凡非通过 AI 工具转化来的流量 / 加粉（如线下转介绍、自然添加、其他人工转介等），统一归入渠道 **「线下转介绍等」** |
| 选项位置 | 渠道下拉在既有 AI / 投放等渠道选项之后，**最后一项**增加「线下转介绍等」 |
| 筛选行为 | 选择具体 AI 渠道时，仅返回该渠道数据；选择「线下转介绍等」时，仅返回非工具来源数据；选择「全部」时上述两类一并统计 |

**渠道选项示意**（顺序，具体投放渠道名称沿用现网）：

```
全部
├─ baidu_doctor_h5 / 百度巧舱 …
├─ douyin_info …
├─ weixin_mp …
└─ 线下转介绍等    ← 新增，置于末尾；非 AI 工具转化均归入此渠道
```

**口径说明**：

1. 每日转化、每日订单金额、医助人效、医助成交在默认「全部」下，汇总数字 = AI 工具各渠道合计 + 「线下转介绍等」。
2. 「线下转介绍等」用户通常无应用 / 应用版本（或为空）；明细列表对应字段展示 `—` 或空，不影响筛选。
3. 从漏斗下钻至明细时：若漏斗当前选的是「全部」，明细带入渠道=全部；若选的是「线下转介绍等」，明细带入该渠道。

### 3.3 漏斗汇总表下钻明细（U05）

在全链路漏斗各汇总表**最右侧新增（或调整）操作列**，链接至用户转化明细页，并通过页内跳转带入时间维度与筛选项；明细页落地后自动按带入条件执行一次筛选。

> 原型实现：[`数据统计2.html`](./数据统计2.html) 为合一页（左侧导航：全链路漏斗 / 用户转化明细）。操作列点击后切换至明细 Tab，并自动写入筛选条件后查询（不再新开独立页面）。

| 来源页面 | 操作文案 | 带入明细的筛选条件 |
|----------|----------|-------------------|
| 每日转化数据 | **加粉明细** | 时间维度=加粉时间；日期起止=该行日期；渠道/子渠道/应用等=当前漏斗筛选条件 |
| 每日转化数据 | **支付明细** | 时间维度=支付时间；日期起止=该行日期；渠道等筛选项带入 |
| 每日订单金额数据 | **数据明细** | 时间维度=支付时间；日期起止=该行日期；渠道等筛选项带入 |
| 医助服务人效统计 | **加粉明细** | 时间维度=加粉时间；日期起止=当前查询日期范围；医助企微 ID（或医助账号）；渠道等筛选项带入 |
| 医助服务人效统计 | **支付明细** | 时间维度=支付时间；日期起止=当前查询日期范围；医助企微 ID；渠道等筛选项带入 |
| 医助成交数据 | **数据明细** | 时间维度=支付时间；日期起止=当前查询日期范围；医助企微 ID；渠道等筛选项带入 |
| 渠道维度数据 | **转化详细**（原「查看详情」改名） | 仍进入渠道产品详细转化页（原逻辑不变） |
| 渠道维度数据 | **加粉明细** | 时间维度=加粉时间；带入该行渠道、子渠道、应用(产品)、应用版本；日期=当前查询范围 |
| 渠道维度数据 | **支付明细** | 时间维度=支付时间；带入同上渠道维度字段；日期=当前查询范围 |

| `channel` / `subChannel` | 渠道 / 子渠道 | |

### 3.4 异步导出 Excel（U01）

#### 3.4.1 交互流程

```
用户点击「导出 Excel」
    ↓
校验：是否已执行筛选（detailQueried = true）
    ↓ 否 → Toast「请先筛选数据后再导出」
    ↓ 是
按钮置灰 + 文案变为「导出中...」
    ↓
后端创建导出任务（携带当前全部筛选条件快照）
    ↓
前端轮询任务状态
    ↓
成功 → Toast「导出成功」+ 下载；失败/超时 → 提示原因并恢复按钮
```

#### 3.4.2 导出字段

| 分组 | 导出列 |
|------|--------|
| 线索信息 | 患者编号、患者昵称、医助名、医助账号、所属团队、渠道、子渠道、应用、应用版本、报告时间、加粉时间、加粉状态 |
| 沟通信息 | 患者对话数、医助回复数、患者图片数、响应状态 |
| 初诊成交信息 | 开方状态、支付状态、支付时间 |
| 复诊成交信息 | 复诊次数、复诊支付时间 |
| 扩展字段 | 开方时间、首单编号、开单医生、首单金额、剂型(汤剂/丸剂)、物流发货时间、成交周期 |

文件命名：`用户转化追踪明细_{时间维度}_{开始日期}_{结束日期}_{导出时间}.xlsx`

### 3.5 统计卡片与趋势图

统计基准跟随「时间维度」。卡片主数字为加总；汤剂 / 丸剂以**弱层级副文案**展示（如 `汤剂 12 单 · 丸剂 8 单`）。

#### 3.5.1 时间维度 = 加粉时间

| 统计卡片 | 统计口径 |
|----------|----------|
| 添加用户数 | 全部渠道加粉次数（删除后重新添加会累加，**不去重**） |
| 已开口用户数 | 客户对话数 > 0 的加粉记录数 |
| 初诊成交单数 | 初诊支付成功订单数；副文案：汤剂 x 单、丸剂 x 单 |
| 初诊成交金额 | 初诊实付金额合计；副文案：汤剂 / 丸剂金额 |
| 复诊成交单数 | 复诊支付成功订单数；副文案：汤剂 x 单、丸剂 x 单 |
| 复诊成交金额 | 复诊实付金额合计；副文案：汤剂 / 丸剂金额 |

#### 3.5.2 时间维度 = 支付时间

| 统计卡片 | 统计口径 |
|----------|----------|
| 初诊成交单数 | 支付日期落在筛选范围内的初诊订单数；副文案：汤剂 / 丸剂 |
| 初诊成交金额 | 同上口径金额；副文案：汤剂 / 丸剂 |
| 复诊成交单数 | 支付日期落在筛选范围内的复诊订单数；副文案：汤剂 / 丸剂 |
| 复诊成交金额 | 同上口径金额；副文案：汤剂 / 丸剂 |

点击卡片切换右侧趋势图聚合指标；对比功能沿用现状，对比基准日期随当前时间维度计算。

趋势图 X 轴：单日按小时、多日按天，时间字段与当前时间维度一致。

### 3.6 核心数据列表（U04）

#### 3.6.1 表头结构

```
🔍 线索信息 (10列) | 💬 沟通信息 (4列) | 💰 初诊成交信息 (3列) | 🔄 复诊成交信息 (2列) | 操作
患者 | 医助 | 团队 | 渠道 | 子渠道 | 应用 | 应用版本 | 报告时间 | 加粉时间 | 加粉状态
患者对话数 | 医助回复数 | 患者图片数 | 响应状态
开方状态 | 支付状态 | 支付时间
复诊次数 | 复诊支付时间
更多详情 | 对话
```

#### 3.6.2 字段定义

**初诊成交信息**

| 列名 | 说明 | 展示 |
|------|------|------|
| 开方状态 | 是否存在初诊处方 | 已开方 / 未开方 |
| 支付状态 | 初诊是否支付成功 | 已支付 / 未支付 / 未开方 |
| 支付时间 | 初诊支付成功时间 | 有则显示时间，否则 `—` |

**复诊成交信息**

| 列名 | 说明 | 展示 |
|------|------|------|
| 复诊次数 | 复诊支付成功订单数 | 整数，无为 `0` |
| 复诊支付时间 | 最近一次复诊支付时间 | 有则显示，否则 `—` |

#### 3.6.3 「更多详情」

- **初诊成交详情**：开方时间、首单编号、开单医生、首单金额、剂型、物流发货时间、成交周期
- **复诊成交详情**（复诊次数 > 0）：历次复诊支付时间、金额、剂型

## 5. 业务规则

| 规则编号 | 规则描述 | 适用场景 |
|----------|----------|----------|
| UR01 | 加粉状态优先级：重复添加 > 已删除 > 正常 | 列表与筛选 |
| UR02 | 时间维度切换仅改变时间命中字段、筛选项显隐与卡片集，其他已选条件尽量保留 | 时间筛选 |
| UR03 | 支付时间维度：初诊或复诊支付时间为空则该端不参与命中；两端均空不返回 | 时间筛选 |
| UR04 | 添加用户数按加粉次数累计，删除后重新添加计入新一次 | 统计卡片 |
| UR05 | 汤剂/丸剂拆分以订单剂型字段为准；无剂型时归入「其他」不计入副文案分子展示时可并入合计 | 统计卡片 |
| UR06 | 漏斗下钻携带完整筛选快照；明细页 `autoQuery=1` 时自动执行筛选 | 下钻 |
| UR07 | 导出任务携带筛选快照，创建后变更不影响已创建任务 | 异步导出 |
| UR08 | 应用版本随应用联动，切换应用后版本重置为「全部」 | 应用筛选 |
| UR09 | 每日数据、医助维度渠道默认「全部」，口径含 AI 工具渠道 + 「线下转介绍等」 | 渠道筛选 |
| UR10 | 非 AI 工具转化（线下转介绍、自然添加等）统一归属渠道「线下转介绍等」，该选项固定为渠道列表末项 | 渠道筛选 |

## 6. 验收标准（UAT）

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| A01 | 异步导出-进行中/成功/失败 | 按钮状态与 Toast 符合交互流程 |
| A02 | 加粉时间维度筛选项 | 展示加粉状态、响应状态、初诊开方/初诊成交/复诊成交状态，文案正确 |
| A03 | 支付时间维度筛选项 | 上述 5 项筛选项隐藏且不参与过滤 |
| A04 | 加粉时间统计卡片 | 6 张卡片含添加用户数、已开口、初诊/复诊单数与金额，副文案含汤剂/丸剂 |
| A05 | 支付时间统计卡片 | 4 张卡片：初诊/复诊成交单数与金额，含汤剂/丸剂副文案 |
| A06 | 核心列表支付与复诊 | 列表含支付时间、复诊次数、复诊支付时间；开方时间仅在更多详情 |
| A07 | 每日转化下钻 | 「加粉明细」「支付明细」带入对应时间维度与日期 |
| A08 | 每日订单金额下钻 | 「数据明细」带入支付时间维度与该行日期 |
| A09 | 医助人效/成交下钻 | 加粉明细 / 支付明细 / 数据明细带入医助企微 ID 与日期 |
| A10 | 渠道维度操作 | 「查看详情」改为「转化详细」；新增「加粉明细」「支付明细」并带入渠道维 |
| A11 | 应用版本联动与列展示 | 版本随应用联动；列表含应用、应用版本列 |
| A12 | 重置 | 恢复默认：加粉时间、今日、状态类=全部、应用=全部 |
| A13 | 全部渠道默认口径 | 每日转化 / 订单金额 / 医助人效 / 医助成交默认渠道=全部，汇总含非 AI 工具来源 |
| A14 | 线下转介绍等 | 渠道下拉末项为「线下转介绍等」；单选该渠道时仅返回非工具转化数据 |

## 7. 原型改造对照

| 区域 | 现状 | 目标 |
|------|------|------|
| 明细筛选栏 | 时间维度两项；开方/成交状态固定展示 | 加粉时间下重命名并新增复诊成交状态；支付时间下隐藏 5 项状态筛选 |
| 明细统计卡片 | 4 张固定卡片 | 加粉时间 6 张 / 支付时间 4 张，含汤剂丸剂副文案 |
| 明细列表 | 已含支付时间与复诊信息 | 保持；详情补充剂型 |
| 每日转化数据 | 无操作列 | 末列增加「加粉明细」「支付明细」 |
| 每日订单金额 | 无操作列 | 末列增加「数据明细」 |
| 医助服务人效 | 无操作列 | 末列增加「加粉明细」「支付明细」 |
| 医助成交数据 | 无操作列 | 末列增加「数据明细」 |
| 渠道维度 | 「查看详情」 | 改为「转化详细」，并增「加粉明细」「支付明细」 |
| 渠道筛选项 | 仅 AI / 投放渠道 | 末项增加「线下转介绍等」；每日数据、医助维度默认「全部」且含非工具来源 |
