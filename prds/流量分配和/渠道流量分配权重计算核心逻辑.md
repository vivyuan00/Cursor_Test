# 渠道流量分配权重计算 — 核心逻辑文档

> 源码入口：`ChannelFlowWeightCacheService.buildChannelFlowWeightBOFromDb()`

---

## 一、整体目标

给定一个渠道编码（如 `baidu_h5`），计算出一棵完整的 **渠道 → 医生 → 医助** 三级流量分配树，每个节点都带有**权重（weight）**和**最终占比（finalProportion）**，供下游业务（如流量路由、坐席分配）使用。

---

## 二、数据模型概览

### 2.1 数据库表

| 表名 | 作用 | 关键字段 |
|------|------|---------|
| `ai_channel` | 渠道主表 | channelCode, channelName |
| `ai_traffic_allocation` | 流量分配配置主表 | id, channelCode, allocationType（DOCTOR/TEAM/ASSISTANT）, trafficAllocationType（COMMON/SPECIFIED） |
| `ai_traffic_allocation_result_data` | 流量分配明细表 | allocationId, allocationItemId, allocationItemName, weight, proportion |
| `ai_doctor_assistant` | 医生-医助关系表 | id, doctorId, assistantName, deptId（团队ID）, weight, proportion |

### 2.2 三个分配层级

| 层级 | allocationType | 说明 |
|------|---------------|------|
| 医生层 | `DOCTOR` | 渠道的流量分给哪些医生，各占多少 |
| 团队层 | `TEAM` | 医生下面有哪些团队参与服务，各占多少 |
| 医助层 | `ASSISTANT` | 团队里具体哪些医助来承接，各占多少 |

### 2.3 两种团队分配模式

| 模式 | trafficAllocationType | 通俗理解 |
|------|----------------------|---------|
| 通用模式 | `COMMON` | 团队里的医助是共享的，直接从关系表读 |
| 指定模式 | `SPECIFIED` | 每个团队有独立配置的医助分配方案，从分配明细表读 |

### 2.4 核心 BO 结构

```
ChannelFlowWeightBO              ← 渠道层
├── channelCode
├── channelName
└── doctorData: List<DoctorAllocationBO>     ← 医生层
    ├── doctorId
    ├── doctorName
    ├── weight（权重）
    ├── proportion（占比，百分比÷100，10位小数）
    └── assistantData: List<AssistantAllocationBO>  ← 医助层
        ├── assistantId
        ├── assistantName
        ├── weight（权重）
        ├── proportion（中间占比）
        └── finalProportion（最终综合占比）
```

## 三、计算流程（9 步）

### 整体流程图

```
输入: channelCode
  │
  ▼
[1] 查询渠道信息 ──── 不存在 → 返回空
  │
  ▼
[2] 构建 ChannelFlowWeightBO 骨架
  │
  ▼
[3] 查询医生分配数据 ──── 无有效医生 → 返回仅含渠道信息的空壳
  │
  ▼
[4] 构建医生占比映射 Map<ChannelDoctorBO, BigDecimal>
  │
  ▼
[5] 查询团队分配数据 ──── 无有效团队 → 走「无团队」简化分支，直接返回仅含医生的数据
  │
  ▼
[6] 构建团队占比映射 Map<teamId, BigDecimal>
  │
  ▼
[7] 根据 trafficAllocationType 分两条路径处理医助数据
  ├── COMMON（团队通用）  → processCommonModeAssistantData()
  └── SPECIFIED（指定医助）→ processSpecifiedModeAssistantData()
  │
  ▼
[8] 构建医生数据列表（医生 + 其下属医助）
  │
  ▼
[9] 计算每个医助的最终综合占比
  │
  ▼
输出: 完整的 ChannelFlowWeightBO（写入 Redis 缓存）
```

---

### 步骤 1~2：查询渠道 & 构建骨架

```java
AiChannelDO channel = channelMapper.selectByChannelCode(channelCode);
// 不存在 → 返回空 ChannelFlowWeightBO
// 存在 → 构建 { channelCode, channelName } 骨架
```

### 步骤 3~4：查询医生分配数据

```
ai_traffic_allocation 表
  └─ 条件: channelCode = ?, allocationType = 'DOCTOR'
  └─ 得到 doctorAllocationDO

ai_traffic_allocation_result_data 表
  └─ 条件: allocationId = doctorAllocationDO.id
  └─ 过滤: weight ≠ 0 且 proportion ≠ 0  → validDoctorList
```

**医生占比** = 数据库中存储的原始 `proportion` 值（百分比形式，如 `30` 表示 30%）。

同时构建映射：`Map<ChannelDoctorBO, BigDecimal> doctorProportionMap`，Key 是 `(channelCode, doctorId)` 的组合。

### 步骤 5~6：查询团队分配数据

```
ai_traffic_allocation 表
  └─ 条件: channelCode = ?, allocationType = 'TEAM'
  └─ 得到 teamAllocationDO（含 trafficAllocationType 字段）

ai_traffic_allocation_result_data 表
  └─ 条件: allocationId = teamAllocationDO.id
  └─ 过滤: weight ≠ 0 且 proportion ≠ 0  → validTeamList
  └─ 特殊处理: allocationItemId 如果含 '-'，取 '-' 之后的部分作为实际 teamId
```

**无团队时的简化分支**：如果团队数据为空，直接构建仅含医生（无医助）的数据返回。

### 步骤 7：医助数据处理（核心分叉）

根据 `teamAllocationDO.trafficAllocationType` 分两条路径：

---

#### 路径 A：COMMON 模式（团队通用）

> 含义：团队下的医助是**共享的**，一个团队可以服务多个医生。

```
1. 查询医助关系表
   ai_doctor_assistant
     └─ 条件: teamId IN teamIdList AND doctorId IN doctorIdList
     └─ 过滤: weight ≠ 0 且 proportion ≠ 0

2. 构建「按医生+团队分组」的医助映射
   buildChannelDoctorAssistantBOMap()
     └─ 按 (doctorId, deptId) 分组
     └─ 组内重新计算占比: 医助占比 = 自身weight / 组内所有医助weight之和

3. 计算中间占比
   对每个医助:
     中间占比 = 医生占比(÷100) × 团队占比(÷100) × 医助组内占比
```

#### 路径 B：SPECIFIED 模式（指定医助）

> 含义：每个团队有**独立指定**的医助分配配置。

```
1. 查询医助分配配置
   ai_traffic_allocation 表
     └─ 条件: channelCode = ?, allocationType = 'ASSISTANT', allocationContent IN teamIdList
     └─ 得到每个团队各自的 allocationId

2. 建立映射: allocationId → teamId

3. 查询医助分配明细
   ai_traffic_allocation_result_data 表
     └─ 条件: allocationId IN [各团队的allocationId列表]
     └─ 过滤: weight ≠ 0 且 proportion ≠ 0

4. 同样构建「按医生+团队分组」的医助映射并重新计算占比

5. 计算中间占比（公式同 COMMON 模式）
   中间占比 = 医生占比(÷100) × 团队占比(÷100) × 医助组内占比
```

**两种模式的区别**：

| 对比项 | COMMON 模式 | SPECIFIED 模式 |
|--------|------------|---------------|
| 医助数据来源 | `ai_doctor_assistant` 关系表 | `ai_traffic_allocation_result_data` 分配明细表 |
| 查询维度 | 按 teamId + doctorId 查关系 | 按 channelCode + allocationType=ASSISTANT 查配置 |
| 适用场景 | 团队内医助共享，不区分渠道 | 每个团队针对特定渠道有独立的医助分配 |

---

### 步骤 8：构建医生数据列表

```
对每个有效医生:
  1. 医生占比 = proportion ÷ 100（转为小数，10位精度）
  2. 查询该医生的所有医助关系
  3. 过滤出在 validAssistantList 中的医助
  4. 组装 DoctorAllocationBO { doctorId, doctorName, weight, proportion, assistantData }
```

### 步骤 9：计算医助最终综合占比（归一化）

```java
// 对每个医生下的医助列表:
assistantTotalProportion = 所有医助 proportion 之和

对每个医助:
  finalProportion = doctorProportion × (assistantProportion / assistantTotalProportion)
```

> **归一化的作用**：确保每个医生下所有医助的 `finalProportion` 之和恰好等于该医生的 `proportion`。

---

## 四、核心计算公式总结

### 4.1 占比转换

```
数据库存储值（百分比）→ 小数占比
例: proportion = 30  →  30 ÷ 100 = 0.3
```

### 4.2 医助组内占比重算（步骤 7）

```
医助组内占比 = 该医助的 weight ÷ 同组(同医生+同团队)所有医助的 weight 之和

例: 医生A+团队X 下有医助1(weight=3)和医助2(weight=2)
  医助1 组内占比 = 3 / (3+2) = 0.6
  医助2 组内占比 = 2 / (3+2) = 0.4
```

### 4.3 医助中间占比（COMMON/SPECIFIED 路径内）

```
医助中间占比 = 医生占比(小数) × 团队占比(小数) × 医助组内占比

例: 医生A占比=0.4, 团队X占比=0.6, 医助1组内占比=0.6
  医助1中间占比 = 0.4 × 0.6 × 0.6 = 0.144
```

### 4.4 医助最终占比（步骤 9 归一化）

```
医助finalProportion = 医生占比 × (该医助proportion ÷ 该医生下所有医助proportion之和)

作用: 保证每个医生下所有医助的 finalProportion 之和 = 医生占比
```

### 5.2 逐步推演

#### 步骤 1~2：查渠道 & 搭骨架

```
输入: channelCode = "baidu_h5"
查 ai_channel 表 → 找到渠道
构建骨架: { channelCode: "baidu_h5", channelName: "百度H5" }
```

#### 步骤 3~4：查医生 & 算占比

```
查 ai_traffic_allocation 表 → allocationType = "DOCTOR" → 找到医生分配配置
查 ai_traffic_allocation_result_data 表 → 找到明细
过滤: weight ≠ 0 且 proportion ≠ 0
```

得到**有效医生列表**：

| 医生ID | 医生名 | weight | proportion（原始百分比） |
|--------|-------|--------|------------------------|
| D001 | 张医生 | 4 | 40 |
| D002 | 李医生 | 6 | 60 |

**占比转换**（百分比 → 小数，保留 10 位）：

```
张医生 proportion = 40 ÷ 100 = 0.4000000000
李医生 proportion = 60 ÷ 100 = 0.6000000000
```

同时构建映射 `doctorProportionMap`：

```
(baidu_h5, D001) → 40    ← 存的是原始百分比，不是小数
(baidu_h5, D002) → 60
```

#### 步骤 5~6：查团队 & 算占比

```
查 ai_traffic_allocation 表 → allocationType = "TEAM" → 找到团队分配配置
查 ai_traffic_allocation_result_data 表 → 找到明细
过滤: weight ≠ 0 且 proportion ≠ 0
特殊处理: allocationItemId 含 "-" 时截取后半段（如 "DEPT-T001" → "T001"）
```

得到**有效团队列表**：

| 团队ID | 团队名 | weight | proportion（原始百分比） |
|--------|-------|--------|------------------------|
| T001 | 上海团队 | 6 | 60 |
| T002 | 北京团队 | 4 | 40 |

构建映射 `teamProportionMap`：

```
T001 → 60    ← 同样是原始百分比
T002 → 40
```

读取 `trafficAllocationType` = **COMMON**（通用模式）→ 走路径 A

#### 步骤 7：处理医助数据（COMMON 模式）

**7a. 查医助关系 & 过滤**

```
查 ai_doctor_assistant 表
条件: teamId IN (T001, T002) AND doctorId IN (D001, D002)
过滤: weight ≠ 0 且 proportion ≠ 0
```

得到有效医助列表：

| 医助ID | 医助名 | 所属医生 | 所属团队 | weight | proportion |
|--------|-------|---------|---------|--------|------------|
| 101 | 小美 | D001 | T001 | 3 | 50 |
| 102 | 小明 | D001 | T001 | 2 | 50 |
| 103 | 小华 | D001 | T002 | 1 | 100 |
| 104 | 小龙 | D002 | T001 | 1 | 100 |

**7b. 按「医生+团队」分组，用 weight 重新算组内占比**

把医助按 `(doctorId, deptId)` 分组：

**组 D001_T001**（张医生 + 上海团队）：

| 医助 | weight | 组内占比计算 | 组内占比 |
|------|--------|------------|---------|
| 小美 | 3 | 3 ÷ (3+2) | **0.60000000000000000000** |
| 小明 | 2 | 2 ÷ (3+2) | **0.40000000000000000000** |

**组 D001_T002**（张医生 + 北京团队）：

| 医助 | weight | 组内占比计算 | 组内占比 |
|------|--------|------------|---------|
| 小华 | 1 | 1 ÷ 1 | **1.00000000000000000000** |

**组 D002_T001**（李医生 + 上海团队）：

| 医助 | weight | 组内占比计算 | 组内占比 |
|------|--------|------------|---------|
| 小龙 | 1 | 1 ÷ 1 | **1.00000000000000000000** |

**7c. 计算每个医助的「中间占比」**

公式：`中间占比 = 医生占比(÷100) × 团队占比(÷100) × 医助组内占比`

**小美**（D001 + T001）：

```
医生占比 = 40 ÷ 100 = 0.4
团队占比 = 60 ÷ 100 = 0.6
组内占比 = 0.6
中间占比 = 0.4 × 0.6 × 0.6 = 0.14400000000000000000
```

**小明**（D001 + T001）：

```
中间占比 = 0.4 × 0.6 × 0.4 = 0.09600000000000000000
```

**小华**（D001 + T002）：

```
中间占比 = 0.4 × 0.4 × 1.0 = 0.16000000000000000000
```

**小龙**（D002 + T001）：

```
医生占比 = 60 ÷ 100 = 0.6
团队占比 = 60 ÷ 100 = 0.6
组内占比 = 1.0
中间占比 = 0.6 × 0.6 × 1.0 = 0.36000000000000000000
```

此时每个医助的 `proportion` 字段被覆写为中间占比：

| 医助 | proportion（中间占比） |
|------|----------------------|
| 小美 | 0.144 |
| 小明 | 0.096 |
| 小华 | 0.160 |
| 小龙 | 0.360 |

#### 步骤 8：组装医生-医助树

对每个医生，查其下属医助关系，匹配步骤 7 的结果，组装成 `DoctorAllocationBO`：

**张医生 D001**：

```
proportion = 40 ÷ 100 = 0.4000000000
├── 小美: weight=3, proportion="0.144..."
├── 小明: weight=2, proportion="0.096..."
└── 小华: weight=1, proportion="0.160..."
```

**李医生 D002**：

```
proportion = 60 ÷ 100 = 0.6000000000
└── 小龙: weight=1, proportion="0.360..."
```

#### 步骤 9：归一化 — 算 finalProportion

公式：`finalProportion = 医生proportion × (该医助proportion ÷ 该医生下所有医助proportion之和)`

---

**张医生 D001** 的归一化：

```
医助 proportion 之和 = 0.144 + 0.096 + 0.160 = 0.400
医生 proportion = 0.4
```

| 医助 | 计算过程 | finalProportion |
|------|---------|----------------|
| 小美 | 0.4 × (0.144 ÷ 0.400) = 0.4 × 0.36 | **0.144** |
| 小明 | 0.4 × (0.096 ÷ 0.400) = 0.4 × 0.24 | **0.096** |
| 小华 | 0.4 × (0.160 ÷ 0.400) = 0.4 × 0.40 | **0.160** |

验证：0.144 + 0.096 + 0.160 = **0.400** = 张医生的 proportion ✅

---

**李医生 D002** 的归一化：

```
医助 proportion 之和 = 0.360
医生 proportion = 0.6
```

| 医助 | 计算过程 | finalProportion |
|------|---------|----------------|
| 小龙 | 0.6 × (0.360 ÷ 0.360) = 0.6 × 1.0 | **0.600** |

验证：0.600 = **0.600** = 李医生的 proportion ✅

## 六、缓存策略

```
读取流程:
  1. 先查 Redis 缓存
     ├── 命中且数据完整（每个医生都有医助）→ 直接返回
     └── 未命中 或 数据不完整 → 走步骤 2
  2. 从数据库计算（上述 9 步）
  3. 结果写入 Redis（有过期时间）
```

**刷新方式**：

| 方式 | 方法 | 说明 |
|------|------|------|
| 同步刷新 | `refreshChannelFlowCache(channelCode)` | 删缓存 → 重新加载，带 ReentrantLock 防并发 |
| 异步刷新 | `asyncRefreshChannelFlowCache(channelCode)` | `@Async` 异步版本 |
| 全量刷新 | `refreshAllChannelFlowCache()` | 遍历所有渠道编码逐个刷新 |
| 全量异步 | `asyncRefreshAllChannelFlowCache()` | 异步全量刷新 |

## 七、关键注意事项

1. **有效数据过滤**：所有层级都要求 `weight ≠ null && weight ≠ 0 && proportion ≠ null && proportion ≠ 0`，不满足条件的记录直接排除。

2. **团队 ID 特殊处理**：`buildTeamResultData` 中，`allocationItemId` 可能带前缀（如 `DEPT-123`），需要截取 `-` 之后的部分作为实际 teamId。

3. **精度控制**：
   - 医生/团队占比转换：10 位小数，`HALF_UP` 舍入
   - 医助组内占比重算：20 位小数
   - 中间占比计算：20 位小数
   - 最终归一化：20 位小数

4. **兜底机制**：`getRandomChannelFlowWeightBO()` 在所有渠道都查不到时，随机选一个已配置的渠道作为兜底。

5. **缓存完整性校验**：读缓存时会检查每个医生下是否都有医助数据，不完整则视为缓存失效，从 DB 重建。
