# 上下文知识库 (Context)

本文件夹用于存放**AI的背景知识库**，帮助AI更好地理解你的业务、项目和产品定位。

---

## 📍 使用场景

### 什么时候用这个文件夹？

- ✅ 新项目启动时，整理项目背景和业务逻辑
- ✅ 需要AI理解特定业务规则和术语
- ✅ 想让AI在生成PRD时自动引用业务上下文
- ✅ 需要统一团队对业务概念的理解

### 为什么需要context文件夹？

> [!IMPORTANT]
> AI每次对话都是"无记忆"的，除非你明确引用文档。context/就是让AI"记住"你的业务背景的地方。

**举例**：

- 不用每次都解释"什么是采购申请单"
- 不用重复说明公司的业务模式
- AI会自动遵循你定义的术语规范

## 📁 文件说明

### 核心文件

#### 01-project-background.md

**项目背景信息**

包含内容：

- 项目名称、目标、愿景
- 所属行业和业务领域
- 核心问题和解决方案
- 项目历史和演进

**AI如何使用**：
理解"我们在做什么项目"，生成的PRD会符合项目定位。

---

#### 02-target-audience.md

**目标用户画像**

包含内容：

- 主要用户角色（采购员、仓管、财务等）
- 用户痛点和使用场景
- 用户技能水平和操作习惯

**AI如何使用**：
撰写用户故事时，使用真实的角色和场景。

---

#### 03-core-strategy.md

**核心策略与原则**

包含内容：

- 产品设计原则
- 技术选型策略
- 优先级判断标准

**AI如何使用**：
在提供方案建议时，遵循你的策略原则。

---

#### 04-business-logic.md

**业务逻辑说明**

包含内容：

- 核心业务流程
- 业务规则和约束
- 系统边界和集成关系

**AI如何使用**：
设计数据模型和流程时，遵循业务逻辑。

---

#### 05-term-glossary.md

**术语表**

包含内容：

- 业务术语定义
- 字段命名规范
- 状态枚举值说明

**AI如何使用**：
统一术语使用，避免歧义。

## 📋 文件组织规范

### 推荐结构

```
context/
├── 01-project-background.md    # 项目背景
├── 02-target-audience.md       # 目标用户
├── 03-core-strategy.md         # 核心策略
├── 04-business-logic.md        # 业务逻辑
├── 05-term-glossary.md         # 术语表
└── [公司名]/                   # 特定企业的背景资料
    ├── company-info.md
    ├── org-structure.md
    └── business-data.md
```

### 文件命名

核心文件使用编号前缀，便于AI按顺序理解：

- `01-` 项目层
- `02-` 用户层
- `03-` 策略层
- `04-` 业务层
- `05-` 术语层

## 🎯 如何让AI使用context内容

### 方法1: 全局引用（推荐）

在`.agent/rules/project-rule.md`中配置：

```markdown
## AI工作时，默认参考以下背景知识：

- @context/01-project-background.md
- @context/04-business-logic.md
- @context/05-term-glossary.md
```

### 方法2: 手动引用

在对话中使用`@`符号引用：

```
@context/05-term-glossary.md

请基于这个术语表，生成"采购订单"的字段清单
```

### 方法3: Workflow自动引用

在workflow中配置自动读取：

```markdown
1. 读取 @context/04-business-logic.md
2. 基于业务逻辑设计数据模型
```

## 💡 最佳实践

### 1. 保持更新

业务变化时，及时更新context文件，AI才能给出准确的建议。

### 2. 结构化编写

使用表格、列表、Mermaid图，便于AI快速提取关键信息。

### 3. 避免冗长

每个文件聚焦一个主题，控制在2000字以内。

### 4. 版本控制

重大业务变更时，在文档顶部记录修订日期。

---

## ⚠️ 注意事项

- **不要放敏感信息**：避免放真实的客户数据、密码等
- **保持简洁**：AI的上下文窗口有限，只放必要的业务知识
- **定期清理**：移除过时的业务逻辑说明

---

## 示例：如何开始

### 第一次使用

1. **复制模板**：从现有的01~05文件中选择需要的
2. **填充内容**：根据你的项目实际情况填写
3. **测试效果**：让AI引用context生成一份PRD，检查是否理解正确

### 日常维护

- 新增业务规则 → 更新`04-business-logic.md`
- 新增术语定义 → 更新`05-term-glossary.md`
- 目标用户变化 → 更新`02-target-audience.md`
