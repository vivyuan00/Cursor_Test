## 1. 需求背景与目标

### 1.1 业务背景

平台已建设 Web 端「全链路漏斗 / 多维度数据统计」能力，覆盖每日转化、订单金额、医助人效、医助成交与渠道维度分析。老板与管理层在移动场景下仍缺少**轻量、可读、可下钻**的经营看板：无法在手机上快速查看今日加粉/成交、分渠道表现、获客成本趋势与医助 Top。

本需求在**复用 Web 端既有数据口径与汇总模型**的前提下，面向移动端交付「素灵CRM数据看板」，优先服务老板侧看数决策。

| 问题 | 现状 | 影响 |
| ---- | ---- | ---- |
| 移动端缺少经营总览 | 仅有 Web 端多维看板，手机访问体验差、信息过载 | 老板无法随时掌握今日加粉、成交与渠道表现 |
| 关键路径长 | Web 端 Tab / 筛选项多，适合运营深挖 | 管理层需要「少筛选、强结论、快入口」 |
| 口径需一致 | 加粉、获客成本、初复诊×汤丸剂等已在 Web 端定稿 | 移动端若口径漂移会导致决策口径冲突 |

### 1.2 需求目标

| 目标编号 | 目标描述 | 衡量方式 |
| -------- | -------- | -------- |
| G01 | 提供移动端登录与个人中心，保障老板看板可安全访问 | 登录 / 记住我 / 退出流程 UAT 通过 |
| G02 | 首页可一览今日加粉、成交、分渠道与医助成交 Top，并跳转详情 Tab | 首页模块齐全，入口跳转正确 |
| G03 | 加粉 / 成交 / 渠道 / 医助人效 / 医助成交五类详情页可筛选、看图、看表 | 与 Web 端核心指标口径抽样对账通过 |
| G04 | 移动端交互符合手机规范：正文字号 12、图表 Top5、条形图不滚动、趋势图可点选数值 | 设计走查 + 真机点选验收通过 |

### 1.3 需求范围

**包含**：

| 编号 | 功能名称 | 功能描述 | 优先级 |
| ---- | -------- | -------- | ------ |
| F01 | 登录与会话 | 账号密码登录、记住我、会话保持 | P0 |
| F02 | 个人中心 | 展示用户名、手机号、所属部门、所属角色；退出登录 | P0 |
| F03 | 首页经营总览 | 今日实时 KPI、分渠道核心、订单核心、近 7 天医助成交 Top5 | P0 |
| F04 | 加粉 | 近一个月默认范围；加粉数趋势 + 平均获客成本趋势；明细表 | P0 |
| F05 | 成交 | 近一个月默认范围；初复诊×汤丸剂堆叠图 + 多系列趋势折线；明细表 | P0 |
| F06 | 渠道 | 快捷/自定义时间；渠道加粉 / 初诊成交 / 获客成本 Top5 条形图；明细表 | P0 |
| F07 | 医助人效 | 默认今日；加粉-支付转化率 Top5；明细表 | P0 |
| F08 | 医助成交 | 默认今日；总订单数 / 总订单金额 Top5（上下结构）；明细表 | P0 |

**不包含**（V1.0）：

- Web 端完整漏斗条形图（AI 工具转化 / 医助转化漏斗全链路）
- 渠道→子渠道→产品→版本树形钻取与「产品详细转化」页
- 来源多选、过滤重复添加、子渠道/产品/版本级投流隐藏规则的完整实现（移动端 V1.0 简化筛选）
- 导出 Excel、查询/重置按钮组（移动端以即时筛选刷新为主）
- 医助开方转化率排行（移动端仅保留支付转化率 Top）
- 渠道「点击-加粉转化率」排行图

> **口径原则**：未在本文单独改写的指标定义，一律以《多维度数据统计》PRD 为准；本文仅描述移动端展示裁剪与交互差异。

## 4. 业务规则

| 规则编号 | 规则描述 | 适用场景 |
| -------- | -------- | -------- |
| R01 | 付费成功以订单 `payment_status=PAID` 且 `paid_at` 非空为准；GMV 取实付金额 | 成交、医助成交、渠道初诊成交 |
| R02 | 加粉数（渠道汇总）= 该渠道新增加企微人数（含 AI 工具添加及投放企微卡等）；行为点击-加粉转化率 = 加粉数（渠道汇总）/行为点击；平均获客成本 = 投流消耗/加粉数（渠道汇总） | 加粉页、渠道页 |
| R03 | 初复诊按诊次判断（与 Web V1.1 一致）；订单按初复诊 × 汤剂/丸剂交叉拆分 | 成交页堆叠图与趋势图、首页订单核心 |
| R04 | 日切与时区为业务日（默认 Asia/Shanghai）；首页「今日」对应当日实时/近实时汇总 | 首页、快捷时间「今日」 |
| R05 | 渠道对外展示使用中文名称（如抖音信息流、百度医生H5），内部编码可映射存储 | 首页、筛选、图表、表格 |
| R06 | Top 排行类图表最多展示 5 条，不支持滚动；横向条形图左右留白、条长受控 | 首页医助 Top、渠道、医助人效、医助成交 |
| R07 | 加粉 / 成交默认时间范围为近一个月（含当日，共约 30 个自然日）；渠道 / 医助人效 / 医助成交默认「今日」 | 各详情 Tab 筛选 |
| R08 | 未登录不可进入看板内容；退出后清除会话；勾选「记住我」可本地记住账号信息（安全策略按现网账号体系落地） | 登录 / 个人中心 |

**详细说明**：

### R02：加粉与获客成本

- **规则描述**：移动端加粉页核心采用「加粉数（渠道汇总）」及衍生获客成本；与 Web 端每日转化 / 渠道维度中投流相关口径一致。
- **适用场景**：加粉趋势、获客成本趋势、加粉明细表、渠道获客成本 Top。
- **处理逻辑**：无加粉时获客成本展示为「—」或 0（与 Web 端空值策略对齐）；线下等无投流渠道获客成本可为「—」。
- **示例**：投流消耗 68200 元，加粉数（渠道汇总）1510 → 平均获客成本 ≈ 45.2 元/人。

### R03：初复诊 × 汤丸剂

- **规则描述**：成交辅助图按「初诊 / 复诊 / 总计」类别堆叠汤剂+丸剂；趋势折线可切换「订单金额 / 订单数」，系列含总金额（或总订单）、初诊汤剂、初诊丸剂、复诊汤剂、复诊丸剂。
- **适用场景**：成交 Tab。
- **处理逻辑**：与 Web「每日订单金额」辅助图表一致（移动端布局改为双卡堆叠 + 下方全宽趋势图）。

### R06：Top5 与条形图

- **规则描述**：排行按指标倒序（获客成本按升序：越低越好）；展示序号 1～5；禁止列表滚动露出第 6 条及以后。
- **适用场景**：所有 Top 条形图模块。

## 6. 页面与交互

### 6.1 页面结构

**系统名称**：素灵CRM数据看板  

**整体结构**：

```
登录页
  ↓ 登录成功
顶栏 Tab：首页 | 加粉 | 成交 | 渠道 | 医助人效 | 医助成交  + 头像入口（个人中心）
  ↓
各业务页：筛选区（如有）→ 图表区 → 数据表
```

**设计规范（移动端）**：

- 常规正文字号 **12px**
- 单列优先；渠道 / 医助人效 / 医助成交图表纵向排列；医助成交两图上下结构
- 首页「近 7 天医助成交 Top」两图上下各占一排
- 渠道中文名展示；趋势图左右撑满，支持点击查看当日数值

### 6.2 登录页

| 元素 | 说明 |
| ---- | ---- |
| 系统名 | 素灵CRM数据看板 |
| 账号 | 必填输入 |
| 密码 | 必填输入 |
| 记住我 | 勾选后下次带出账号（及现网策略允许的记住项） |
| 登录 | 提交校验；失败提示「账号或密码不能为空 / 错误」 |

### 6.3 个人中心

| 字段 | 说明 |
| ---- | ---- |
| 用户名 | 登录账号或展示名 |
| 手机号 | 脱敏展示（如 138\*\*\*\*6688） |
| 所属部门 | 组织架构部门名 |
| 所属角色 | 如老板看板管理员 |
| 退出登录 | 二次确认后退出 |

入口：顶栏右侧头像；支持返回首页。

### 6.4 首页

#### 6.4.1 今日实时

| 卡片 | 指标 | 交互 |
| ---- | ---- | ---- |
| 今日加粉数（全量） | 当日加粉总量 + 较昨日涨跌幅 | 点击进入「加粉」 |
| 今日成交订单数 | 当日支付成功订单数 + 较昨日涨跌幅 | 点击进入「成交」 |

#### 6.4.2 今日分渠道核心数据

- 按加粉倒序列出渠道（中文名）
- 每渠道展示：今日加粉、今日初诊成交及较昨日涨跌
- 入口：「渠道 ›」

#### 6.4.3 今日订单核心数据

- 初诊：订单数 / 金额，拆分汤剂、丸剂
- 复诊：订单数 / 金额，拆分汤剂、丸剂
- 入口：「成交 ›」

#### 6.4.4 近 7 天医助成交 Top

| 图表 | 内容 | 格式 |
| ---- | ---- | ---- |
| 总订单数 Top5 | 近 7 天医助总订单数 Top5，带序号 | 横向条形图，上下布局之一 |
| 总订单金额 Top5 | 近 7 天医助总订单金额 Top5，带序号 | 横向条形图，上下布局之二 |

约束：最多 5 条、不滚动、左右留白、条长受控。入口：「医助成交 ›」。
