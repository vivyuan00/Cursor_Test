## 二、业务板块

### 2.1 核心业务：中医健康管理服务（占比95%+）

#### AI舌诊引流
+ **工具形式**: 小程序/H5舌诊自测
+ **核心功能**:
  - 拍照舌象 + AI特征识别
  - 生成标准化舌诊报告
  - AI医生Agent初步问诊
+ **投放渠道**:
  - 付费采买：百度大搜、腾讯广点通、抖音信息流
  - 外部合作：健康类App、内容平台免费换量
  - 生态互惠：合作伙伴提供流量，按成交分成

#### 私域运营与转化
+ **载体**: 企业微信
+ **运营角色**: 医助 + AI话术SOP
+ **转化路径**:
  - 用户添加医助企微 → 医助基于CRM+AI话术沟通 → 问诊生成病历与AI处方 → 医生确认 → 付费 → 代煎发货 → 随访复诊

#### 服务产品
+ **标准服务**:
  - 中医体质辨识
  - 个性化调理方案
  - 中药代煎配送
+ **增值服务**:
  - 医生一对一深度问诊
  - 疗程管理（7天/14天）
  - 复诊提醒与随访

### 2.2 其他业务（探索期，占比<5%）
+ **AI舌诊SaaS输出**: 向第三方健康平台提供舌诊API能力（按调用量收费）

## 三、角色与核心流程

### 3.1 主要角色
+ **用户/患者**: 健康管理服务最终使用者
+ **医助**: 通过AI工具进行标准化问诊、沟通、促单、随访
+ **医生**: 负责处方审核、调整与确认，提供专业背书

### 3.2 用户流程
1. 用户在第三方平台（百度、抖音、合作App）使用AI舌诊工具
2. 系统生成舌诊报告，并触发AI医生Agent进行基础问诊
3. 若用户有进一步沟通需求，点击“添加医生助理”进入企微

### 3.3 医助流程
1. 用户添加企微后，医助通过CRM系统查看用户画像与舌诊数据
2. 基于AI话术SOP与用户沟通，补充问诊信息
3. 系统自动生成结构化病历 + AI推荐处方
4. 将病历与处方推送至医生工作台
5. 医生确认签字后，订单状态变为“待支付”，医助发送支付码
6. 用户支付后，订单推送到代煎中心
7. 制作过程可视化（物流追踪、煎药进度）
8. 后续提供随访与复诊提醒

### 3.4 医生流程
1. 登录医生工作台，查看待确认订单
2. 查阅用户病历总结、AI问诊对话历史
3. 对AI处方进行调整（加减药材、调整剂量）
4. 电子签名确认，订单进入支付环节

## 四、技术系统与AI能力

### 4.1 核心系统
+ **AI舌诊引擎**: 基于深度学习的舌象分类与特征提取模型
+ **AI医生Agent**: 自然语言问诊 + 规则推理，输出初步诊疗建议
+ **CRM管理系统**: 用户标签、触达记录、AI话术SOP、转化漏斗
+ **医助工作台（企微插件）**: 一键调用话术、查看病历、推送处方
+ **医生工作台**: 病历汇总、处方调整、签字确认
+ **数据中台**: 用户行为、转化归因、渠道ROI分析

### 4.2 系统现状与痛点
+ **现状**: 
  - AI舌诊与CRM已打通，但数据中台尚在建设中
  - 医助依赖AI话术，但部分复杂场景仍需人工介入
  - 医生签字流程偏人工，效率待提升
+ **痛点**:
  - 用户跨渠道来源无法统一归因
  - CRM与医生工作台数据同步存在延迟
  - 缺少实时BI看板，运营决策依赖周报

## 七、行业特性与挑战

### 7.1 互联网中医健康管理行业特点
+ **信任门槛高**: 用户对线上中医处方信任度低于线下
+ **政策监管严**: 互联网诊疗、处方药、患者隐私保护等合规要求
+ **转化周期长**: 从舌诊体验到付费通常需要3-7天跟进
+ **复购依赖疗效**: 用户是否复购强烈依赖实际效果与服务体验

### 7.2 核心挑战
+ **AI准确率与边界**: AI舌诊不能替代临床诊断，需明确免责与辅助定位
+ **医助人效与标准化**: 如何在不牺牲体验前提下规模化复制高转化话术
+ **医生资源瓶颈**: 签约医生数量有限，签字环节容易堆积
+ **数据隐私与安全**: 舌象、病历、处方属于敏感健康数据
